# ImageJevBench Box track — method (v0.1, 14 Oct 2026)

**What it measures.** Can a model find one described thing in an image and return its bounding box? This is the
`box` question type that TypeSafe added in Jev 1.14.0: the input is one image plus a short description
("the leftmost dog in `photo`", "the signature field in `photo`"); the answer is four edges (`top`, `bottom`,
`left`, `right`, each a fraction 0..1 of the image size) and a confidence 0..1.

The Box track is its own track. It does **not** feed into the ImageJevBench core Capability Score or composite,
so it never changes the core ranking.

## Items
| Family | What | Gold box | Licence |
|---|---|---|---|
| Photos — single | one obvious instance of an object category | COCO 2017 val annotation | images CC BY 2.0 / CC BY-SA 2.0 (Flickr, per item), annotations CC BY 4.0 (COCO Consortium) |
| Photos — referring | one of several same-category objects, picked by a spatial relation with a safety margin ("the rightmost truck", "the largest umbrella", "the cup closest to the laptop") | COCO 2017 val | as above |
| Photos — small | a unique object covering < 2 % of the image | COCO 2017 val | as above |
| Documents | rendered invoices, forms, receipts, letters, labels ("the signature field", "the IBAN") | exact, from the page layout | CC BY 4.0, ImageJevBench (generated by us) |
| UI screenshots | rendered web/app screens ("the close button of the dialog", "the unread badge") | exact, from the page layout | CC BY 4.0, ImageJevBench |

- **Public set: 300 items** (photos 200, documents 50, UI 50), published with images and gold boxes for reproduction.
  **Sealed set: 600 items** from the same generators with disjoint images; held back for official runs.
  A separate 60-item dev split is used only to pick each chat model's prompt format, never scored.
- Images stay inside Jev's limits (256–1568 px per side) and are sent unchanged (no resizing).
- No faces as targets. Persons appear as whole-body COCO boxes only.
- Quality control: rule checks (uniqueness, size, crowd annotations, confusable categories, separation margins for
  referring expressions), then a second annotator pass over every public and dev item with the gold box drawn on
  the image. The first COCO draw lost 36 of 240 items there (mostly referring expressions whose reference object was
  not visible, overlapping animals, slivers at the image edge, and COCO boxes that cover only part of the object or
  the wrong thing); none of the 120 synthetic items was dropped. The COCO rules were tightened and the gaps refilled
  with new images that passed the same check. Hard but correct items are kept. Every item records its provenance
  (COCO image and annotation id, or generator template and seed) and licence.
- Caveat: COCO images are widely used in training; contamination is possible for the photo part. The documents and UI
  part is new and not on the internet.

## How systems are asked
- **Jev 1.14** (`jev-1.14.0`): the native `box` question through the TypeSafe API, image as an asset, header
  `TypeSafe-Danger-Zone-Images: true`. Native confidence.
- **Chat vision models** (OpenAI-compatible): image + prompt at temperature 0. Each model gets two prompt formats on
  the dev split — a generic one (edges as 0..1 fractions) and the model family's own grounding format (e.g. Qwen's
  `bbox_2d` in 0..1000) — and the better one is frozen before the scored run. Confidence is the model's stated
  confidence that its box is right (IoU ≥ 0.5); where none is given, 0.5 is used.
- No retries except transport errors (429/5xx). A missing or unreadable answer scores IoU 0.
- **Baselines**: "full image" and "centre prior" (the mean dev box) show what a model gets without looking.

## Scores
| Column | Definition |
|---|---|
| **Box Intelligence** | 100 × mean IoU (intersection over union of answer and gold box) |
| Acc@0.5 / Acc@0.75 | share of items with IoU ≥ 0.5 / ≥ 0.75 |
| **Calibration** | 100 × (1 − ECE / 0.5), ECE over 10 confidence bins with "IoU ≥ 0.5" as the event — the same mapping as the core track |
| **Box Capability Score** | mean of Box Intelligence and Calibration (the track headline) |
| Ranking floor | a system is ranked only if its Box Intelligence is at least twice the better baseline's and ≥ 90 % of its answers are valid. Without the floor, a system that always answers "the whole image" with low confidence would be well calibrated and rank high without finding anything. |
| Latency | p50 / p95 end-to-end seconds per box |
| Cost | USD per 1,000 boxes: API list price × tokens (Jev: $0.042 per 1M input tokens, output free), or measured GPU seconds × $1.19/GPU-h for self-hosted models |

Breakdowns by family and object size; 95 % bootstrap interval on Box Intelligence.
Not measured: Kimi K2.6 (a thinking model; at its lowest reasoning setting it spent 4,096 tokens per box and mostly gave no answer) and Mistral Small (OpenRouter rate-limited 55 of 60 dev requests). Jev 1.13 rejects Box questions (HTTP 400), as documented.
Hosted closed APIs see only the public set unless an official sealed run is logged under the rotation rules.
