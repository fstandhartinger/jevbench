# JevBench v1.2 addition: Pixel (LivioGama, potion-128M zero-shot)

Submitted by the author, measured on the **public items only** — 231 of the 534
frozen decisions: easy 48/72, standard 72/96, hard public 111/220, judge 0/146.
A partial row, shown without a rank, same rule as `jqv`: the held-out items and
the judge tier stay on the maintainers' machines.

## What Pixel is

Pixel is a deterministic retrieval and planning tool (MIT,
[github.com/LivioGama/pixel](https://github.com/LivioGama/pixel)), not a trained
Jev-class model. Its `pixel classify` op answers a bounded label set the way a
zero-shot classifier does:

- embed the question text (`instructions` + `\n\n` + `state`) and each option's
  criterion text with the same static embedding model Pixel uses for its
  semantic channel — `minishlab/potion-multilingual-128M` (Model2Vec), loaded
  once and resident (`pixel classify --jsonl` serves one decision per stdin
  line);
- cosine similarity per label, then a fixed-temperature softmax
  (`tau = 0.07`, CLIP's value, chosen a priori) → a probability distribution
  over the exact label set.

No LLM, no network call, deterministic per model revision. The distribution is
the system's own softmax over its similarities → `probs_source = native`.

## Mapping (fixed before the run)

| Question type | Criteria → spec |
|---|---|
| `noul` | `{"yes": criteria["true"], "no": criteria["false"]}` |
| `choice` | criteria dict as-is (keys are the labels) |
| `score` | criteria list → `{"<level index>": description}` |

A label with no criterion embeds as its own name. `text` is
`instructions + "\n\n" + state`; non-string state is rendered as JSON.

## How it ran

- Adapter: `jevbench/adapters/pixel_local.py` — spawns `pixel classify --jsonl`,
  one JSONL request per decision, per-decision wall latency measured at the
  write/read boundary.
- Hardware: submitter's Apple M4 Max, serial, one decision at a time. Latency
  carries the standard self-hosted adjustment (×2 + 0.15 s, an assumption).
  Raw p50/p95 kept in the row.
- Cost: no provider tariff — encoder-class estimate per the common rules
  (DeepInfra base-encoder class, $0.005/M in, $0/M out; ~86 mean input tokens
  on easy/standard, ~1,169 on hard, chars/4). A static Model2Vec model is
  strictly cheaper than a transformer encoder of that class, so this errs high.
- Results: `results/v1.2/additions/pixel.json`, `pixel-per-task.json`.

## Scores on the public items

easy 64.6 % · standard 36.1 % · hard (public half) 45.0 % — all 231 answers
schema-valid, 0 failures. Calibration (hard, public): ECE 0.207, fidelity 68.7
on the 10 public probability items → 63.6.

To rank the row, the maintainers' side runs the same adapter against the
held-out and judge items — the `pixel` binary is a single static executable
(`brew install` / cargo build), so `pixel_local` reproduces on any CPU.
